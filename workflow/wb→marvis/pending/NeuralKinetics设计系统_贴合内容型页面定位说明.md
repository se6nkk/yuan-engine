# NeuralKinetics 设计系统 · 贴合「元框架引擎」内容型页面的定位说明

> 配套文档：`NeuralKinetics界面风格提炼.md`（单页风格拆解）、`NeuralKinetics多页面风格延展规划.md`（原按落地页写的延展规划）
> 撰写日期：2026-07-29
> 背景：用户明确要求「设计系统要根据我们的页面内容做调整，不能完全硬套模板」。本文把 NeuralKinetics 美学从"整页模板"重新定位为"元框架引擎 reader 的视觉皮肤基底"，并给出具体收敛清单。

---

## 〇、一句话定位

**NeuralKinetics 提供的是「美学灵感 / 令牌基底 / 通用组件」，不是要整页替换元框架引擎。**

元框架引擎的主体是本就该有的 **reader 皮肤**（五层渐进认知框架、长文渲染、结构化可视化模块）；NeuralKinetics 只负责把这套 reader 的皮肤「做得更有机、更耐看」——双主题变量、流体球氛围背景、pill / 软面板等通用件。

---

## 一、两个页面的气质差异（为什么不能硬套）

| 维度 | NeuralKinetics 录屏（落地页） | 元框架引擎（实际页面） |
|------|------------------------------|------------------------|
| 页面类型 | **SaaS 营销落地页** | **内容型阅读器** |
| 核心内容 | 极少文字、单一 Hero、一句 slogan | 五层渐进认知框架、大量长文 + 结构化模块 |
| 内容密度 | 内容占比 40%~55%，巨幅留白 | 高密度，长文为主，需要持续可读性 |
| 主交互 | 看一眼就走（浏览） | 长时间阅读 + 翻页 + 模块导航 |
| 视觉焦点 | 流体球本身就是主角 | 流体球必须退到内容之后，内容才是主角 |
| 典型区块 | Hero / Features / Pricing | 领域分类(脑图) / 发展脉络(时间轴) / 误区(对照) / 底层原理… |

> **结论**：把落地页的「超大留白 + 单一 Hero + 不对称 footer」整页套到阅读器上，会让长文失去承载结构、可读性崩坏。正确做法是**只取通用件（令牌、流体球、pill、软面板、nav/footer），页面骨架按 reader 重写**。

---

## 二、NeuralKinetics 设计系统里「该复用」与「不该套」的清单

### ✅ 直接复用（令牌 / 通用组件层）
- **双主题变量体系**：`:root` 亮调 + `@media (prefers-color-scheme:dark)` 暗调（已处理了暗调 `--blob-blend: screen` 等关键坑）。这部分直接并入 reader 的现有变量即可。
- **流体球组件**（`.blob-wrap` + 3 `.blob` 漂移动画）：作为**全局氛围背景**保留。
- **Pill**（实心/描边）、**Eyebrow**、**Section header**、**Soft panel**（`.panel`）、**Nav bar**、**Footer**：这些是脱离具体页面的通用件，reader 也用得上（标签、区块标题、内容托底容器、顶栏、页脚）。
- **动效 / 无障碍规范**：`prefers-reduced-motion`、入场 `opacity+translateY`、blob 仅用 transform/opacity —— 全站通用。

### ❌ 不要套（落地页专属骨架）
- **整页居中 Hero**（Display 60px+ 大标题 + 双色字重 slogan）：阅读器不需要这种"一眼营销"，页面级标题用适中 H1 即可。
- **"内容占比 40%~55% 巨幅留白"原则**：阅读器是内容密集页，要反过来——用 soft panel 提高密度、承载长文，而不是留白。
- **Features / Pricing / About / Contact 那套 landing 页面骨架**：元框架引擎没有这些页；它的"页面"是**五层框架的每一层**，结构完全不同。
- **之前给小T 的 `neuralkinetics-demo.html`**：那是**落地页原型**，仅用于演示令牌/球/组件"长什么样"，**不是集成目标**。小T 集成时只从中提取令牌与通用件，不要照搬 demo 的 landing 布局。

## 三、针对元框架引擎的具体收敛调整

### 3.1 流体球：从「焦点」降级为「氛围背景」
- **透明度下调**：现有 `--blob-opacity` 亮调 .55 / 暗调 .50，**降到 .30~.40**，让球明显退到内容之后。
- **位置固定、不再做页面变体强调**：阅读器是全站同一形态，不需要 Home/Features/Pricing 那种"球左移/下沉"的页面变体（那是落地页叙事手法）。统一一个安静的位置即可。
- **内容区可读性兜底**：长文阅读区（`.reader` / `.module-content`）可叠一层**极淡的 `--bg` 半透明遮罩**（`background: color-mix(in srgb, var(--bg) 82%, transparent)` 之类），让文字在任何球色位置都清晰。这是阅读器特有的、落地页不需要的让步。
- **尺寸收敛**：球的 `vw` 尺寸可略缩，避免在大屏上糊成一片抢戏。

### 3.2 字号比例：正文优先，Display 克制
- **正文基准**：沿用 reader 现有 `0.9rem`(≈14.4px)，不要改成落地页的 15px Body（保持与现有长文一致）。
- **Display / H1 大标题（clamp 40~64px）**：仅在「整站首页 / 框架总览」极少数页面级标题使用，**禁止**在五层内部的模块标题滥用。模块标题维持现有 `module-title`(0.95rem) 量级。
- **双色字重副标题**：这个技巧**只适合页面级 Lead**，模块内不要用，否则干扰长文阅读。

### 3.3 留白与密度：提高密度、用 soft panel 承载
- 落地页的"巨幅留白"原则**反转**：阅读器用 soft panel（半透明玻璃片）把长文轻轻托住、分隔模块，密度按可读性走。
- 模块之间用现有 `--rule`（极淡分隔线）或 soft panel 间距，不靠 landing 式大空当。

### 3.4 组件映射（reader 已有 ↔ NeuralKinetics 通用件）
| 元框架引擎现有 | 对应 NeuralKinetics 通用件 | 动作 |
|----------------|---------------------------|------|
| 五层分页框架 | —— | 保留并强化（这是 reader 核心，不动） |
| 长文 `.module-content` | Soft panel `.panel` | 可让 `.module-content` 引用 `.panel` 的视觉（玻璃感），但保留分页结构 |
| 标签 / 切换 pill | Pill | 直接统一为 NeuralKinetics pill |
| 顶栏 / 页脚 | Nav / Footer | 统一为 NeuralKinetics 样式 |
| 领域分类脑图 / 时间轴 / 误区对照 | —— | 保留（已有可视化语言），仅让它们的配色跟随双主题令牌 |
| 配色 `--ink/--rule` 等 | 双主题变量 | 并入，保证暗调自动翻转 |

## 四、给小T 的明确指令（写进派工单）

> **不要整页替换 `index.html` 的 reader。** 把 `neuralkinetics.css` 当作「视觉皮肤层」叠加：
> 1. 引入双主题令牌，**并入** reader 现有变量（不另起系统）。
> 2. 在 `<body>` 加 `.blob-wrap` 氛围背景，按 §3.1 降透明度、固定位置、加阅读区遮罩。
> 3. pill / nav / footer / section-header 等通用件**统一**为 NeuralKinetics 样式。
> 4. **保留并强化**现有的五层分页、长文渲染、脑图/时间轴/误区对照等结构化模块；它们的配色改为引用双主题令牌，实现亮/暗自动翻转。
> 5. **不要**引入 Features/Pricing/About/Contact 等落地页骨架，也**不要**照搬 `neuralkinetics-demo.html` 的布局。

## 五、验收点（补充到一致性清单）
- [ ] 流体球为氛围背景（透明度 .30~.40），长文阅读区文字在任何球色位置都清晰（有遮罩兜底）。
- [ ] 正文基准仍 ≈0.9rem(14.4px)，未因套用落地页而被改成 15px 或被 Display 大标题挤占。
- [ ] 五层分页 / 长文渲染 / 已有可视化模块（脑图/时间轴/对照）结构完整保留，未被落地页骨架替换。
- [ ] 颜色全部走双主题变量，系统亮/暗切换时整站（含已有模块）自动翻转、暗调球清晰可见。
- [ ] pill / nav / footer 视觉统一为 NeuralKinetics 通用件；无新增硬编码色。
