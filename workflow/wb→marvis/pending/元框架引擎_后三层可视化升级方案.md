# 元框架引擎 · 后三层（第三/四/五层）可视化升级方案

> 版本：v1 · 2026-07-29 · 提出：小万(WB) · 目的：把第一/二层已落地的可视化语言，延伸到第三/四/五层，消除"平铺大段文字"导致的阅读疲劳。

---

## 1. 背景与诊断

`index.html` 已在第一、二层做了**选择性可视化**：

- ✅ 第二层 · 模块2 领域分类 → 思维导图 SVG（`generateMindmapDOM`）
- ✅ 第二层 · 模块3 发展脉络 → 时间轴（`generateTimelineHTML`）
- ✅ 第二层 · 模块4 常见误区 → 三段式结构化 HTML（`generateMisconHTML`）

但**第三 / 四 / 五层共 9 个模块**（`renderResult()` 中走 `else` 分支的 `marked.parse()`）全部是平铺 Markdown 大段文字：

| 层 | 模块 | 现状 |
|----|------|------|
| 第三层 深层逻辑 | 5 底层原理 | 大段文字 |
| | 6 最新前沿 | 列表平铺 |

## 2. 设计原则（必须沿用，不可另起炉灶）

第二层之所以好看，是因为它套用了同一套**扁平有机视觉语言**。后三层必须复用，否则会出现"两套设计系统"：

1. **主题跟随**：reader 已有 `toggleTheme()` 与明暗切换，新模块必须用 reader 现有 CSS 变量/类名，不能写死颜色。
2. **扁平 / 有机**：无重边框、无卡片阴影；用 `border-radius:999px` 的 pill、半透明 soft panel、细连线来表达层级。
3. **双主题安全**：所有颜色走变量，暗调下不出现"黑球消失"类问题（参考 NeuralKinetics 设计系统踩坑）。
4. **降级优先**：关系网络 / 术语云在窄屏（≤640px）必须降级为可读列表，不能溢出。
5. **无障碍**：入场动效用 `prefers-reduced-motion` 尊重；不依赖颜色单一通道传递信息。
6. **解析鲁棒**：LLM 输出不总是规整，每个生成器都要有 `marked.parse()` 兜底（像 `generateMindmapDOM` 在 `categories.length===0` 时回退）。

**视觉语言参考资产**（供实现者对照，已交付小马 box）：
- `neuralkinetics.css` / `neuralkinetics-demo.html` —— 双主题 + 流体球 + pill/soft panel 规范
- `mindmap-svg.zip`（用户级 skill）—— 脑图/时间轴/误区对照三套模板与配色
- `output/误区对照教程.md` —— `foreignObject` 自然换行等技巧

## 4. 四类策略详解

### ① 卡片网格 `generateCardGridHTML(raw, variant)`
通用生成器，按 `variant` 切换卡片模板：
- `issue`：难题卡（标题 + 一句描述 + 状态 pill：未解/活跃/突破中）
- `scenario`：场景卡（emoji/图形图标 + 标题 + 一句话）
- `lesson`：课程卡（序号 + 微任务 + 时长 pill + 勾选框）
- `tool`：工具卡（名称 + 类型 pill + 一句说明），按类型分组

实现：解析现有 Markdown 列表/段落 → 抽成数组 → 输出 `.viz-card` 网格（CSS grid，响应式 1/2/3 列）。**兜底**：解析不出则 `marked.parse()`。

### ② 阶梯流 `generateStepperHTML(raw)`
模块11 专属。把四阶段解析为横向（宽屏）/ 纵向（窄屏）阶梯：
- 每阶段：序号节点 → 阶段名 → 一句说明
- 节点间用带箭头的方向连线（贝塞尔或 CSS 伪元素）
- 视觉语言复用误区对照的"左右/上下分栏 + 圆点"风格

### ③ 关系网络 `generateNetworkDOM(raw)`
模块5（因果链）与模块8（辐射图）共用，传 `mode` 区分：
- `chain`：A → B → C 因果链（横向节点 + 箭头）
- `radial`：中心概念在中间，学科/机制辐射连线
- 用 SVG 绘制节点圆 + 连线；暗调下连线/节点走变量色
- **降级**：窄屏渲染为缩进列表

### ④ 术语胶囊云 `generateTermCloudHTML(raw)`
模块10 专属。把 8 个术语渲染为大小一致/错落的 pill 云：
- 每个 pill 点击 → 触发已有的 `showGlossary()` 高亮解释（复用第 1010 行 glossary 包裹逻辑）
- 不用字号夸张的"词云"，保持扁平 pill 语言

## 5. 技术接入方案

### 5.1 复用现有生成器
- `generateMindmapDOM`（领域分类）
- `generateTimelineHTML`（发展脉络 **+ 模块6 最新前沿** 直接复用）
- `generateMisconHTML`（常见误区）

### 5.2 新增生成器（挂在 `index.html` 现有生成器旁，约 1673 行之后）
- `generateCardGridHTML(raw, variant)`
- `generateStepperHTML(raw)`
- `generateNetworkDOM(raw, mode)`
- `generateTermCloudHTML(raw)`

### 5.3 改造 `renderResult()` 分发（约 975–1007 行）
在现有 `if/else if` 链中追加分支（注意匹配优先级，避免与"核心概念/术语"现有分支冲突）：

```js

  content = generateTimelineHTML(mod.content || '');
  moduleExtraClass = ' module-timeline';

// 7 核心难题 / 9 现实映射 / 12 自主学习课程 / 13 工具箱 → 卡片网格
else if (title.includes('核心难题')) {
  content = generateCardGridHTML(mod.content || '', 'issue');
  moduleExtraClass = ' module-cards';
}
else if (title.includes('现实映射')) {
  content = generateCardGridHTML(mod.content || '', 'scenario');
  moduleExtraClass = ' module-cards';
}
else if (title.includes('自主学习课程') || title.includes('课程')) {
  content = generateCardGridHTML(mod.content || '', 'lesson');
  moduleExtraClass = ' module-cards';
}
else if (title.includes('工具箱') || title.includes('工具')) {
  content = generateCardGridHTML(mod.content || '', 'tool');
  moduleExtraClass = ' module-cards';
}
// 11 推荐学习路径 → 阶梯流
else if (title.includes('学习路径') || title.includes('路径')) {
  content = generateStepperHTML(mod.content || '');
  moduleExtraClass = ' module-stepper';
}
// 5 底层原理 / 8 跨领域连接 → 关系网络
else if (title.includes('底层原理') || title.includes('原理')) {
  content = generateNetworkDOM(mod.content || '', 'chain');
  moduleExtraClass = ' module-network';
}
else if (title.includes('跨领域') || title.includes('连接')) {
  content = generateNetworkDOM(mod.content || '', 'radial');
  moduleExtraClass = ' module-network';

// 10 核心概念索引 → 术语胶囊云（保留现有 glossary 包裹逻辑）
```
